# 05. 주니어 취업 관점 분석 — 이 프로젝트는 어디까지 무기가 되는가

> 작성 관점: 한국 차량 SW/임베디드 시장 기준, **신입(~경력 2년 미만) 지원자** 가정.
> 실제 채용공고 키워드를 수집해 이 저장소와 1:1 매핑했다 (§3 참조).

---

## 0. 한 줄 결론

> **"면접을 부르는 이력서" 까지는 충분히 가능한 수준의 증거물.**
> 다만 이 프로젝트 하나로 끝나는 게 아니라, ① 실물 타겟 경험, ② 검증 자동화(CI/정적분석),
> ③ 툴 용어 접촉(CANoe/Unity/정적분석) 3가지를 덧붙여야 "합격 패턴"에 진입한다.

## 3. 주니어 합격 방정식 (우선순위)

```
합격 ≈ ① 증거물(이 프로젝트+α) × ② CS 기초(OS/네트워크/C 자체) × ③ 협업 흔적(Git 이력, CI)
       + ④ 전형 통과력(코딩테스트/자소서/면접 태도)
```

- **① 은 이미 강함**: 대부분의 신입 이력서는 "C 할 줄 앎 + 학교 아두이노 과제" 수준. 
  이 저장소는 바이트 기대값까지 계산된 테스트 + 추적 매트릭스를 갖춘 **검증 가능한 아티팩트**다.
- **② 는 별도 준비 필수**: volatile/메모리 모델/OS 스케줄링/CAN 물리층 질문은 어디서든 나옴.
- **③ 는 1~2주면 채워지는데 안 채우는 사람이 많다** — 최고 가성비 구간.
- **④ 의 코딩테스트**: 대기업 공채(오토에버/모비스)는 알고리즘 테스트가 따로 있다. 이 프로젝트가 대체하지 못함.

## 4. 이력서/포트폴리오 표현 가이드

### 나쁜 예
> "AUTOSAR 학습, CAN 프로토콜 공부, 창업동아리 활동"

### 좋은 예 (수치+검증+추적 문장)
> - **PC 기반 미니 AUTOSAR ECU 설계/구현(C, 3.6k LOC)**: MCAL(Dio/Adc/Can)–CanIf–PduR–Com–RTE–SWC 적층, 설정 테이블 기반으로 신호 추가 시 로직 수정 0줄 달성, 통합테스트로 TX/RX 전 경로 바이트 기대값 검증
> - **ISO 15765-2 / ISO 14229-1 스택 구현**: SF/FF/CF/FC 상태기계+STmin 페이싱, UDS 9개 서비스·NRC 우선순위·S3/보안지연(SecurityAccess 3회 실패→0x36→0x37 시퀀스) 구현, 단위테스트 32건
> - **기능안전 메커니즘 구현**: E2E Profile1(Alive counter+CRC8), SecOC(AES-CMAC+신선도, 재전송/위조 거부 테스트), WdgM 데드라인 감시 — AES/CMAC 는 FIPS-197/RFC4493 벡터로 검증
> - **ASPICE 산출물 실습**: SRS↔구현↔TC 추적 매트릭스, 코드리뷰 체크리스트, 검증 보고서 템플릿 작성
> - (추가 후) **GitHub Actions CI: gcc 빌드+전체 테스트+gcov 커버리지 자동 리포트**

규칙: ① 숫자 ② 검증 방법 ③ "무엇을 증명하는지" — 이 세 요소가 없는 프로젝트 문장은 스킵당한다.
면접관은 ~20초에 이력서 1장을 본다. GitHub 링크 → README 의 capstone 출력 캡처가 첫 화면이어야 함.

## 5. 기술면접 예상 질문 ↔ 이 프로젝트로 준비하는 답

| 질문 | 답의 뼈대 (어디에서 연습?) |
|---|---|
| volatile 왜 쓰나? 스레드 안전인가? | ex1_2: "최적화 억제, 동기화는 아니다 — 그래서 BSRR/원자연산" |
| 인터럽트에서 메인으로 데이터 어떻게 넘기나? | ex1_3 링버퍼 + 유실 카운트 + 한 칸 희생 이유 |
| FPU 없으면 실수 연산을? | ex1_4 Q포맷 = CAN 시그널 factor/offset 과 같은 사고방식 |
| AUTOSAR 계층 설명/왜 나누나 | ex2 계층도 + "SimMcu 만 교체하면 이식" |
| Com 과 Dcm 차이 | ex2 vs ex3: 신호 중심 vs 진단 메시지 중심, PduR 로 갈라지는 지점 |
| PDU 라우터 왜 필요? | ex2: Com/Dcm 이 같은 CanIf 공유, 라우팅 테이블 |
| NRC 0x13 vs 0x31, 0x36 vs 0x37 | ex3 표 + TC_UDS_031 시나리오(지연 중 재시도) |
| TesterPresent 왜 있나? S3 란? | ex3: TC_UDS_060, 지연(10s)>S3(5s) 상호작용까지 말하면 가산점 |
| CAN 시그널 Motorola 패킹 설명 | ex3: start7/len12 → AB C0 예제로 화이트보드 시연 |
| E2E 와 SecOC 차이 — 둘 다 필요한가? | ex4: 무작위 고장 vs 악의적 공격, capstone 에서 나란히 시연 |
| Watchdog 은 뭘 잡는 건가? | ex4: 프로그램 흐름 감시, capstone PHASE 4 재연 |
| MISRA 왜? 예시 규칙 | ex1: unsigned 시프트, 1<<31 문제 |
| ASPICE SWE.1~6 아나? 추적성이란? | ex4/aspice: 매트릭스 라이브 시연, CL2 지적사항(양방향 추적성) |
| SecOC 신선도는 왜 필요한가. 재전송 공격이란? | ex4: TC_SECOC, replay 카운터 분리 설계 |
| 모르는 걸 물어봤을 때 태도 | "모릅니다. 다만 SimMcu 교체 방식으로 검증하는 실험은 설계할 수 있습니다" 같은 **실험 설계형 답변** 이 이 프로젝트의 체취와 맞음 |

## 7. 현실 체크 (리스크)

- **경력 선호 시장**: 오토에버/모비스 등은 신입 공채 슬롯이 좁다. 하청 SI/교육과정/인턴 경로를 부끄러워하지 말 것 — 2~3년 내 Tier-1 이직이 표준 루트다.
- **학력/전공 필터**: 일부 대기업 계열은 전공(전자/컴공) 필터 유지. 비전공은 오픈소스 기여·실물 보드 실적·자격 없이도 증거물 승부 (반도체 팹리스/중견이 상대적으로 개방적 [2][3]).
- **이 프로젝트의 한계를 스스로 말할 것**: "시뮬레이션 환경이며, 실제 HIL/타겟 검증은 아니다"라고 선을 긋는 태도가 오히려 신뢰를 준다 (서른 대 면접관은 뻥튀기를 바로 잡아낸다).
- **연봉/처우 변동성 큼**: 업계·직군별 편차가 크므로 잡플래닛/블라인드/공고문 직접 비교 권장. 이 문서에서 수치는 단정하지 않는다.
- **SDV 트렌드 주의**: Adaptive AUTOSAR/C++/SOA 비중 확대. Classic 을 먼저 잡되, Adaptive 키워드(Ara::Com, SOME/IP)는 면접 어휘로만 준비할 가치가 있음.
