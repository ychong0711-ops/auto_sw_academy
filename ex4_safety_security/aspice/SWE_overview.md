# Automotive SPICE (SWE) — 이 저장소를 프로세스 관점에서 보기

ASPICE 는 "무엇을 코딩했나"가 아니라 **"요구사항 → 설계 → 구현 → 검증"이 추적 가능한가**를 평가합니다.
이 프로젝트는 아주 작지만 SWE.1~SWE.6 의 산출물 흐름을 전부 재현합니다.

## SWE 프로세스 ↔ 이 저장소 산출물

| 프로세스 | 목적 | 이 저장소의 대응 산출물 |
|---|---|---|
| SWE.1 소프트웨어 요구사항 분석 | 무엇을 만들지 명문화 | 각 파일 헤더의 `[SRS_xxx_NNN]` 요구사항 태그, 본 문서 모음, docs/ |
| SWE.2 소프트웨어 아키텍처 설계 | 구조/인터페이스 정의 | docs/02 의 계층도, EX2 의 레이어별 디렉터리(Mcal/Bsw/Rte/Swc), 헤더 파일들 |
| SWE.3 상세 설계 및 유닛 구현 | 유닛 설계+코딩 | 각 `.c` 파일 + 요구사항 태그 주석 (`[SRS_COM_010]` 등) |
| SWE.4 소프트웨어 유닛 검증 | 유닛 테스트 | `TC_xxx` 케이스(mini_test), 벡터 테스트(FIPS-197, RFC4493) |
| SWE.5 소프트웨어 통합 및 통합 테스트 | 유닛 연결 검증 | EX2 통합 테스트, capstone 통합 데모 |
| SWE.6 소프트웨어 자격 테스트(qualification) | 요구사항 대비 최종 검증 | `ctest` 전체 수행 결과, verification_report.md |

## 추적성(Traceability) 사용법

1. **요구사항 → 코드**: 모든 구현 함수에 `[SRS_xxx_NNN]` 주석
2. **요구사항 → 테스트**: 테스트 메시지/이름에 `TC_xxx_NNN` 부여
3. **집계**: `traceability_matrix.csv` 에 SRS ↔ 함수 ↔ TC 3방향 매핑
4. 실무 도구: DOORS / Codebeamer / JIRA 와 테스트 툴을 연결해 자동 집계

### 현장 팁
- CL2(레벨 2) 심사에서 가장 많이 지적받는 것: **양방향 추적성 누락**(코드에 SRS 없음, 테스트에 TC 없음), **일관성 없는 리뷰 기록**, **SWE.4 전략 문서 부재**
- 코드리뷰는 `code_review_checklist.md` 처럼 체크리스트 기반으로 "수행됐다는 기록"을 남겨야 함
- MISRA-C / CERT-C 정적 분석 결과도 SWE.4 산출물
