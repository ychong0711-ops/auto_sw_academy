리뷰 대상: __________  리뷰어: __________  일자: __________  PR/커밋: __________

## 1. 요구사항/추적성
- [ ] 모든 신규/수정 함수에 대응하는 SRS 태그가 있는가
- [ ] SRS 와 구현이 1:1 로 의미가 일치하는가 (과잉 구현/누락 없음)
- [ ] 테스트 케이스(TC)가 함께 추가되었는가, traceability_matrix.csv 갱신되었는가

## 2. MISRA-C / 코딩 규칙 (핵심만)
- [ ] 비트 연산은 unsigned 타입만 사용, 시프트량 < 비트폭
- [ ] 암묵적 타입 변환(승격/축소)이 의도적인가, 캐스트 명시 여부
- [ ] 매직 넘버 사용 금지 (상수/매크로 정의)
- [ ] switch 는 default 포함, 루프 탈출 조건 명확
- [ ] 재귀 없음, 동적 메모리(malloc) 없음
- [ ] 포인터 역참조 전 NULL 체크, 배열 경계 명시

## 3. 아키텍처/계층 (AUTOSAR)
- [ ] 상위 계층이 하위 인터페이스를 "걷잡고" 직접 접근하지 않는가 (SWC→MCAL 직접 호출 금지)
- [ ] 설정 데이터(_Cfg)와 코드 로직이 분리되어 있는가
- [ ] 새 PDU/신호 추가 시 테이블(Cfg) 변경만으로 되는가, 코드 수정이 필요 없는가
- [ ] 컴파일 타임 의존성 방향이 올바른가 (상위가 하위 헤더만 include)

## 4. 타이밍/동시성
- [ ] MainFunction 주기와 모듈 남부 타이머 단위가 문서화됐는가
- [ ] ISR ↔ task 공유 변수에 volatile / 원자적 접근 / 상호배제 대책이 있는가
- [ ] 상태 변수 갱신 순서가 재진입에 안전한가

## 5. 안전/보안
- [ ] 외부 입력(CAN/UDS)에 대한 길이/범위 검증을 가장 먼저 하는가
- [ ] 실패 시 안전 상태로 수렴하는가 (NRC, 폐기, 기본값)
- [ ] 보안 자산(키/시드)이 코드에 하드코딩되지 않았는가 (데모 제외 주석 필수)
- [ ] 카운터/신선도/CRC 검증 로직에 우회 경로가 없는가

## 6. 가독성/유지보수
- [ ] 함수 길이 적절(대략 60줄 이내), 범위(복잡도) 과다 분기 없음
- [ ] 이름이 AUTOSAR 관습(API 네이밍: Module_Action)을 따르는가
- [ ] 변경 이유를 설명하는 커밋 메시지/주석이 있는가
